# 대칭이동 수업자료 설계서 (공통수학2 - 도형의 이동 단원)

작성일: 2026-09-13

## 1. 목적
교과서 문제풀이 대체가 아니라, "왜 대칭이동을 하면 좌표가 이렇게 바뀌는가"를 학생이
직접 손으로 확인하고 느끼게 하는 체험형 디지털 수업자료. 계산 반복 연습은 종이 학습지로
진행하며, 이 웹페이지는 좌표평면 위에서 점·직선·원·포물선·자유곡선을 직접 움직이며
대칭이동을 경험하는 데 집중한다.

## 2. 다루는 수학 내용
- 점 P(x, y)의 대칭이동: x축 (x,-y) / y축 (-x,y) / 원점 (-x,-y) / 직선 y=x (y,x)
- 도형 f(x,y)=0의 대칭이동: x축 f(x,-y)=0 / y축 f(-x,y)=0 / 원점 f(-x,-y)=0 / y=x f(y,x)=0
- y=x 대칭의 증명 아이디어(중점이 y=x 위에 있음 + PP'이 y=x에 수직)를 시각적으로 재구성
- 심화(점(a,b) 대칭, 직선 x=a/y=b 대칭, 합성, 자기 자신으로의 대칭)는 이번 범위에서 제외.
  단, "발견형 질문" 섹션에서 텍스트 질문으로만 가볍게 언급(예: "x축 대칭 두 번 하면
  원점 대칭과 같을까?", "원의 중심이 원점이면 어떤 대칭이동을 해도 도형이 그대로일까?")
- 실생활 응용(반사/최단거리) 미니 위젯은 이번 범위에서 제외 (추후 단계에서 추가)

## 3. 프로젝트 구조
새 프로젝트 폴더 `C:\dev\symmetry\` (dandan과 별도 프로젝트).

```
C:\dev\symmetry\
├── index.html              # 메인 수업 페이지 (탭/섹션 구조)
├── style.css                # 공통 스타일
├── coordinate-plane.js      # 좌표평면 공통 유틸 (격자/축, 좌표↔픽셀 변환) - 모든 위젯 공유
├── symmetry-point.js        # 위젯 A: 점의 대칭이동
├── symmetry-shape.js        # 위젯 B: 도형의 대칭이동 + 자유곡선 대칭 놀이
├── canvas-input.js          # 펜 필기 입력 캔버스 (재사용 컴포넌트)
├── understanding-check.js   # "이해함/헷갈림/모르겠음" 3단계 버튼 컴포넌트
├── data-store.js            # 저장/불러오기 추상화 인터페이스 (localStorage 구현체)
├── teacher-dashboard.html   # 교사 대시보드 뼈대 (목데이터)
└── teacher-dashboard.js
```

렌더링 방식: **HTML5 Canvas 2D, 외부 라이브러리 없음.**
이유: 드래그, 자유곡선 그리기, 애니메이션이 모두 필요하며 매 프레임 다시 그리는 캔버스
방식이 SVG DOM 조작보다 단순하고 성능이 예측 가능함. dandan 프로젝트의 기존 2D 캔버스
위젯(`equation-canvas`, `properties-canvas`)과 구현 방식/톤이 일치함.
모든 입력은 Pointer Events(`pointerdown`/`pointermove`/`pointerup`)로 구현하여 마우스,
터치(태블릿), 펜을 하나의 코드 경로로 처리한다(터치 전용 fallback 불필요, 단 필요 시
`touch-action: none` 등으로 스크롤 간섭 방지).

파일은 더블클릭으로 바로 열리도록 ES 모듈/로컬 fetch를 쓰지 않고 클래식
`<script src="...">` 순서 로딩 + 전역 함수/객체 노출 방식을 사용한다.

## 4. 데이터 모델 & 저장 인터페이스 (`data-store.js`)

### 학생 식별
- 최초 접속 시 이름/번호 입력 모달 → `localStorage`에 `{studentId, studentName}` 저장
- 이후 접속 시 자동으로 이전 식별자 사용 (재입력 없음)

### 기록 스키마
```js
{
  studentId: string,      // 예: "1-05" (번호 기반) 또는 UUID
  studentName: string,
  activityId: string,     // 예: "point-widget", "shape-widget", "discovery-q1"
  type: "note" | "understanding",
  payload: string,        // note: 캔버스 dataURL, understanding: "understood"|"confused"|"unknown"
  timestamp: number       // Date.now()
}
```

### 인터페이스 (전부 Promise 반환 — Firestore 교체 시 호출부 무수정)
- `getCurrentStudent(): Promise<{studentId, studentName} | null>`
- `setCurrentStudent(name, no): Promise<void>`
- `saveRecord(record): Promise<void>`
- `getRecords(filter?): Promise<Record[]>`

지금 단계에서는 위 4개 함수를 전부 `localStorage` 기반으로 구현한다. 교사 대시보드도
이 함수들만 호출하도록 만들어, 추후 `data-store.js` 내부 구현만 Firestore 호출로
바꾸면 나머지 코드는 수정하지 않아도 되게 한다.

## 5. 페이지 흐름 (`index.html`)

dandan의 탭/섹션 패턴을 참고(상단 sticky 탭바 + 섹션 전환)하되, 파일은 여러 JS로 분리한다.

1. **도입 - 연결 지도**: "평행이동 → 대칭이동 → (다음 단원)" 타임라인을 간단한 HTML/CSS
   다이어그램으로 표시 (캔버스 불필요). 도형의 이동 단원 전체에서 현재 위치를 보여줌.
2. **질문 던지기**: 데칼코마니/호수에 비친 산/당구공 반사 등 실생활 소재 제시 후
   "이 대칭을 좌표로 나타내면 어떻게 될까?" 질문 제시.
3. **위젯 A - 점의 대칭이동 탐구** (4절 참고)
4. **위젯 B - 도형의 대칭이동 탐구** (5절 참고, 자유곡선 대칭 놀이 포함)
5. **원리 설명**: 위젯 A의 좌표평면을 "설명 모드"로 재사용하여 중점 표시 → 수직 표시를
   "다음 단계" 버튼으로 하나씩 켜가며 y=x 대칭의 증명 아이디어를 재구성.
6. **발견형 질문**: 계산이 아닌 "그럴 것 같아? 왜?" 형태의 질문 목록. 심화 아이디어
   (합성, 자기 자신 대칭)는 여기서 텍스트 질문으로만 언급.

각 섹션 하단에 `canvas-input.js`(필기 입력)와 `understanding-check.js`(3단계 버튼)를
배치한다.

## 6. 위젯 A - 점의 대칭이동 (`symmetry-point.js`)

- 좌표평면 위 점 P를 Pointer Events로 자유롭게 드래그.
- x축/y축/원점/y=x 토글 버튼: 누르면 대칭점 P'이 선형 보간 애니메이션으로 나타나고,
  P/P' 좌표를 실시간 텍스트로 표시.
- **예측 모드**: 토글 on 시 캔버스를 클릭/탭하면 예상 위치에 반투명 점 표시 → "확인"
  버튼 클릭 시 실제 대칭점이 애니메이션으로 나타나며 예측과의 거리(픽셀/좌표 차이)를
  텍스트로 비교 출력.
- **한번에 비교 모드**: P, x축대칭점, y축대칭점, 원점대칭점 4개 점을 색상 구분하여
  동시에 표시하는 체크박스 모드.

## 7. 위젯 B - 도형의 대칭이동 (`symmetry-shape.js`)

- 도형 종류 드롭다운: 직선(y=mx+n) / 원((x-a)²+(y-b)²=r²) / 포물선(y=a(x-h)²+k).
  각 파라미터는 슬라이더로 실시간 조절.
- 대칭 기준(x축/y축/원점/y=x) 선택 시 원래 도형(파란색)과 대칭이동된 도형(주황색)을
  함께 그리고, 대입 과정을 텍스트로 실시간 표시
  (예: `y = mx+n` → x축 대칭 대입 `-y = mx+n` → 정리 `y = -mx-n`).
- **자유곡선 대칭 놀이** (이번 단원의 핵심 체험 파트): 학생이 캔버스에 펜/마우스로
  자유곡선을 그리면, 그려지는 좌표를 실시간으로 선택된 대칭 변환식에 대입하여 대칭상을
  동시에(그리는 즉시) 함께 그린다. 정형화된 도형이 아니어도 대칭이동이 항상 성립함을
  체감하는 것이 목적이므로 지연 없이 실시간으로 그려지도록 구현한다.

## 8. 교사 대시보드 (`teacher-dashboard.html`, `teacher-dashboard.js`)

- 목데이터로 학생 × 활동별 이해도 현황을 테이블로 표시 + 이해함/헷갈림/모르겠음 개수 요약.
- `data-store.js`의 `getRecords()`를 호출하는 구조로 만들어, 실제 데이터 연동 시
  목데이터 생성 부분만 실제 호출로 교체하면 되도록 설계한다.
- 학생 필기(canvas dataURL)는 목록에서 썸네일로 볼 수 있게 한다(선택적으로 클릭 시 확대).

## 9. 구현 순서
1. 점의 대칭이동 위젯 (`coordinate-plane.js` + `symmetry-point.js`)
2. 도형의 대칭이동 위젯 (`symmetry-shape.js`, 자유곡선 대칭 놀이 포함)
3. 필기/이해도 컴포넌트 (`canvas-input.js`, `understanding-check.js`, `data-store.js`)
4. 페이지 조립 (`index.html`, `style.css`) - 도입~발견형질문 전체 흐름 구성
5. 교사 대시보드 (`teacher-dashboard.html`, `teacher-dashboard.js`)

각 단계마다 중간 결과물을 보여주고 확인받은 뒤 다음 단계로 진행한다.

## 10. 범위 밖 (Out of scope, 이번 단계)
- 실생활 응용 미니 위젯(반사/최단거리 - C)

- Firestore 등 실제 백엔드 연동 (인터페이스만 준비)
- 문제 풀이 연습 콘텐츠 (종이 학습지 영역)
